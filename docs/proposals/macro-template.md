# マクロ型紙の提案（未承認・調査途中）

関連: #155、#107、#100。design.md の変更を承認するものではない。

## 案と未解決点

変換時にマクロ行の固定部分をパースし、穴とその位置・引数型を保存する。実行時は穴の値を型別に処理し、静的に特定できない行には別の処理を用意する案を検討する。全文法を生成物に同梱しない選択肢になりうるが、現時点では未確認。値が構文の区切りや別の命令を作る場合もあるため、任意の値に対する正しさとフォールバックは未設計である。成功例だけを固定形と見なしてはならない。

実測と再現方法は [findings.md](../findings.md#マクロの具体値による型紙試探155暫定)。Java 26.3 の文法と6候補の限定試探で 3,630 行中 3,615 行にパース可能な例があるが、静的に固定できる割合ではない。版ごとの文法差、穴同士の組み合わせや任意の値は調査していない。

追加の試探では27行で異なる形が見つかった。固定と判定する限定条件に該当する行は0、3,603行は未判定だった。固定率は未判定である。型紙の単一形を全行に仮定できず、未判定を固定形として扱う根拠もない。詳細は #282 の集計を参照。

## 保守的な判定の調査（#282）

対象を「展開後にパース成功した場合の節の種類・名前・型・ジャンプの列」と定義する。失敗を含む全代入で同じ結果になることや、引数内部の構造・変換結果の固定とは別の性質である。実行可能な値の制約が分からないため、文字列を任意とし、同じ名前の穴には同一値を使う。成功例2つの列が異なれば不定と証明できるが、有限試探が1形でも固定は証明できない。成功例がなければ空集合についての固定という扱いを避けて未判定とする。

候補として、穴を任意文字列とする過大近似を文法・引数パーサー上で記号実行し、到達可能な成功形を全て列挙する方法が考えられる。同名の穴を独立に近似しても到達可能形を漏らさなければ固定の証明には安全だが、実現不可能な形が混じり未判定が増える。成功形が1つ以下であることに加え実際の成功例があれば固定、異なる実際の成功例があれば不定、その他は未判定にできる。過大近似だけから不定とは結論しない。

ただしこれは未実装の案である。再帰的な `execute ... run`、引用・入れ子・可変長の引数、リテラル優先、版差、同名穴の等値制約について、到達可能性を漏らさない抽象化と停止条件が必要になる。解析不能・時間切れは未判定へ落とす。現行パーサーと Java との一致も前提にできず、合成入力と各版の実サーバーで比較する必要がある。実行時にパースできない場合の扱いと内部値の変換は別途必要であり、この調査は型紙方式を採用する判断ではない。

実行時に必要な候補は、穴の値を型別に読む処理（座標、セレクタ、NBT・NBT パス、ID、名前など）と、その値の変換に必要な対応表である。どの表をどの範囲で同梱するか、サイズやライセンス上の扱いは未確定。#238 で空白と境界、#239 で ID と storage 定数、#240 で必要データとサイズを調べる。

## 判断への暫定的な示唆

#107 では、型紙案を全文法同梱の代替候補に含める。ただし固定可能率とフォールバックが未確定のため、全文法が不要と結論しない。#100 では、版に対応した穴の型・位置の表現、失敗時の扱い、Java の実行結果との比較を分割時に検討する。現行の試作は具体値一例の観測であり、実行機能ではない。
