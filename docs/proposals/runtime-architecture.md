# 未承認の提案：ランタイムの構成

#141 の調査であり、#95 で所有者が選ぶまで決定ではない。以下の設計上の効果は推定。#93 の実行モデルと #94 の状態の正本、#107 のデータの扱いは未承認であり、それぞれの判断後に整合を再確認する。

## 1. パッケージ境界

| 候補 | 利点と制約 |
| --- | --- |
| 中核を `packages/core` に置く（推奨） | 既存パーサ・NBT と型を共有し Node でも実行可能。Minecraft API を持ち込まない境界の維持が必要 |
| 解釈器を別パッケージにする | 責務を分離できるが core への依存と公開 API の管理が増える |

Script API のホストは別パッケージ、出力パックの組み立ては converter に置く。`bridge-pack` は検証専用に保ち、製品が依存しない。API の配置や名称は実装前に検証する。

## 2. ホストの契約

中核は Java の条件、セレクタのフィルタ・sort・limit、成否、分岐と予算を評価し、ホストは候補エンティティの取得、ブロック・状態の読み書き、ネイティブ委譲、保存、時刻を提供する案を推奨する。取得した候補の順序、距離と乱数、失敗、ロードされていない領域を明示してフェイクで再現可能にする。全検索をホストに委ねる案は実装が単純だが Java の並べ替えや上限の意味がホストに散らばる。Java と BE の候補集合の一致は未確認。

#93 未決定のため両契約を残す。A（同期解釈）は同期読み取り・保留書き込みのオーバーレイと同期成否を要求し、同期確定できない委譲は対象外とする。B（予約後実行）は依存単位の予約・順序・後の結果を表し、予約の成功を実行成功としない。どちらも外部との競合を検出できない場合を警告する。詳細は [実行モデル案](runtime-execution-model.md)、状態の正本は [状態案](runtime-state.md) を参照。

## 3. 受け渡し

| 候補 | 利点と制約 |
| --- | --- |
| 通常関数は変換時に版付き IR、マクロ展開後は実行時にパース（推奨） | 起動時の反復解析を避けられる見込み。IR の版・入力文法版・非対応命令を記録し、未知版は拒否する必要がある |
| 本文を全て渡して実行時にパース | 形式が単純だが起動時や実行時のコストと文法依存がある |

[PoC](../../poc/runtime-load/README.md) の同梱案は圧縮前 12,624,623 bytes、雛形作成を除いた起動要求から初回パースまで 602 / 783 / 613 ms。JSON.parse のみ 159 / 193 / 178 ms。実測の範囲と限界は同 README を参照。#107 の判断待ちなので Mojang の commands.json 同梱を決定しない。元の commands.json ファイルを同梱せず全ノードを圧縮 JSON に再構成し同じ対応表を含む案は 12,210,907 bytes（生成サイズのみ）。変換物の扱いは #107 で判断する。同梱しない案は独自の文法と必要な対応表を用意する。独立した手書き1命令・石1件の試作は 50,929 bytes だが実用的な網羅性はなく、全機能版の大きさ・性能・権利は未確認。対応表も生成過程に Mojang データを使うため、既存表をそのまま使う案が同梱なしに該当するとは決められない。#107 の結論と完全な代替データの検証が必要。

## 4. ビルド

| 候補 | 利点と制約 |
| --- | --- |
| 出力時に必要モジュールを束ねる（推奨） | core の Node 非依存部分だけを配布できる。依存と成果物の検査が必要 |
| bridge-pack と同様の tsc 出力 | 既存手順を使えるが、core の相対 import と `.ts` 拡張子の出力・データの生成を扱う必要がある |

PoC は型除去と拡張子書き換えを使う実験であり製品ビルドの決定ではない。`erasableSyntaxOnly` と相対 `.ts` import は維持し、最終 JS の import 解決と Node API 不在を BDS で検証する。

## 5. 解釈の形

明示的なフレームと実行キューで関数呼び出し・`return`・分岐を表し、単一起動の命令数、深さ、分岐数に予算を設ける案を推奨する。上限超過・パース失敗・ホストエラーは成功扱いせず診断する。正確な Java の上限・順序やエラー伝播は未確認で、正解データとの比較が必要。再帰的な直接呼び出しは簡単だが深さと中断の制御が難しい。#93 の A は同じハンドラ内で予算まで同期実行し、B は依存単位を予約して後で順序通り実行する。どちらも未承認で、外部の条件付きチェーンへの成否の返し方が異なる。

## 6. テストの層

Node のフェイクホストで IR、分岐、予算、状態と Java 正解データを高速に比較し、BDS では API 制約、起動、永続化、ネイティブとの境界を実測する案を推奨する。Node のみでは API・順序を保証できず、BDS のみでは再現と網羅が難しい。Java の正解データの対象範囲（#96）と各ホストの差を明示する。
