# リソースパック変換範囲（未承認の提案）

[#119 の判断](https://github.com/tapu18/mc-je2be-map-converter/issues/119#issuecomment-7153933674)では段階的に対応し、M2 ではリソースパックを変換しない。下記原案の M2 に粒子基盤とパック組込みを入れる部分は採られていない。M3 以降の段階は [互換性の段階計画](compatibility-milestones.md) を参照し、粒子・音は M5 の族とする。資源ごとの詳細や外部コード採用はこの提案で承認されていない。以下は判断前の案を記録として残したもの。

調査日: 2026-11-23。#135 の所有者判断により、独自粒子をリソースパックで生成し、Molang 変数とランタイムで引数を扱うことは前提である。

## 根拠と読み方

下表の「変換」は限定した形式に変換できる候補、「近似」は同じ振る舞いを保証できない候補、「対象外」は今回自動変換しない提案であり、実装済みの意味ではない。**未確認**は資料やソースに基づく候補で、対象版・実クライアントでの再現性は未検証。**実測**は条件と結果を明記する。検証課題は親 #119 の承認後、機能ごとの実装・PoC で追跡する。

使用状況は [既存の匿名集計](../corpus-survey.md#リソースパック進捗predicateルートテーブル) の19 ZIP（18ワールドと単体データパック1本）からの保存ファイル・定義数で、作品数や実行頻度ではない。重複、無効パック、版違い、旧新形式の併存を含む。不正 JSON はファイル数に含み定義数から除外する。描画・参照解決は未検証。言語と粒子は同じ調査を再実行し、`resources()` の対象ディレクトリに `lang` と `particles` を追加して数えた。言語は拡張子を問わないファイル数、粒子は JE の `assets/<namespace>/particles/` 配下のファイル数である。他のモデル・テクスチャ等の数は既存集計と一致した。再現には `scripts/survey_corpus.py` を一時コピーし、対象正規表現の `items` に `|lang|particles` を追加して、元の調査と同じ入力・引数で実行する。コマンド JSONL は非公開の一時領域にのみ出す。原本の名前・内容は掲載しない。

推奨は PackConverter を**比較実験の候補**とし、採用は保留すること。両候補とも固定版で合成パックを入力し、対象 JE / BE 版、出力と欠落、ライセンス・依存・同梱データを確認する。MIT 表示だけで配布資材の権利まで確認したことにはならない。外部コード・データを採用する場合は別途所有者の判断を得る。私有マップを外部サービスへ送らない。

## 段階案

- **M2**: #135 の粒子方式の基盤、生成パックの manifest・ワールドへの組込みと未対応報告。#147 のクライアント検証を前提に粒子の品質を確認する。既存変換器の合成入力による比較を行う。
- **M3**: 対応表で明確に結び付く基本テクスチャ、音声、言語の限定変換を提案。入力版・未対応・欠落をレポートし、対応先が不明なら黙って成功扱いにしない。
- **M4**: 表示エンティティと連携するモデル・custom_model_data、bitmap/space フォントを優先。条件選択・UV・文字幅の合成例を JE / BE クライアントで比較し、未対応部分を通知する。
- **M5 以降 / 個別判断**: 複雑なモデル条件、TTF、特殊シェーダー、PBR 等を需要と PoC に基づいて判断。シェーダーの汎用変換は約束しない。

段階は既存の [M2〜M5 の目的](../design.md) に沿う案で、粒子以外は決定ではない。M3 の基本変換と M4 のモデルが相互依存する場合、共通の出力形式を先に検証する。完了判定には合成データの自動テスト、出力パックの実クライアント確認、対象版・欠落の明示が必要。

## #119 に求める判断

1. 粒子に加えて、基本テクスチャ・音声・言語を M3、モデルと基本フォントを M4 に段階導入する（推奨）。使用量の多い資材を扱い、未確認の同等性は実機検証と警告で管理する。
2. 粒子のみ先行し、他の機能は個別判断まで対象外にする。工数とリスクを抑えるが、配布マップの見た目・音を多く失う。
3. モデル・フォントを含む広範囲を早期に一括対応する。再現を早く狙えるが、仕様差と保守コストが未検証で見積もりが難しい。

いずれも #135 の粒子決定を維持し、外部変換器の採用・配布物の権利は別判断とする。
