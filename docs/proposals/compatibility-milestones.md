# 互換性の族と段階の組み直し案（#106）

所有者は段階の組み直しと詳細を委ねた（[#106 の判断記録](https://github.com/tapu18/mc-je2be-map-converter/issues/106#issuecomment-7096756298)）。下記の案 A を採用し、design.md 7章と GitHub のマイルストーンに反映する。具体的な段階の関門は引き続き所有者に確認する。各族 Issue は `family` を介した全行の追跡先であり、1 PR に収まる子 Issue に分割する。行の `issue` は個別判定の追跡に残し、方式が実証済みであることを意味しない。

## 採用した計画

推奨は下表の案 A。案 B は現行の部品別 M3〜M5 を維持し、族 Issue を横断の追跡だけに使う。A は進行を支える機能から成果を評価しやすい一方、境界をまたぐ機能と検証の分割が必要。B は既存の説明を保てる一方、族の全体像と進行上の効果が段階から見えにくい。頻度と進行必須性は別物なので、いずれも #69 のギミック評価で必須・任意・未検証を区別する。

| 段階 | 案 A の到達点 | 族と順序（依存関係は候補） |
| --- | --- | --- |
| M2 | 関数・スコア・storage・マクロ・schedule と起動口を、自作マップで検証 | command #179 の中核部分は既存 #97〜#103。#104 が関門。その他の族の全対応を要求しない |
| M3 | 進行に関係する状態・エンティティと命令を優先し、必須ギミック単位で検証 | command #179 の残り、entity #182、effect #181、attribute #177、game_rule #183。#98〜#103 と仮想 NBT の範囲を先に定める |
| M4 | データ駆動の報酬・進捗・アイテムと UI を扱う | component #180、loot_condition #185、loot_entry #186、loot_function #187、advancement_trigger #176、click #178、hover #184。#97 の取込、#99 の状態、#98・#102 の実行とホストに依存する見込み |
| M5 | 粒子・音・大規模な動きと性能を広げる | particle #188、sound #189。#135 の決定と #147、#119、#98・#102・#103 に依存する見込み。進行を止める成否の問題は M5 を待たず別途優先する |

各族は段階をまたいで部分対応できる。表は族の完了目標であり、ギミックへの影響や PoC の結果に応じて子作業を前倒しする。段階完了には対象子 Issue と #69 に沿った検証・既知の欠落の記録が必要。全マップのクリアを推定しない。M3〜M5 の具体的な関門は子 Issue の切り出し時に定量化し、段階の関門の変更は所有者に確認する。

## 根拠と限界

[集計](../compatibility-summary.md) は 19 作品の静的な観測。command は 176,602 件の行対応・17作品、entity は 5,319・16作品、particle は 1,442・13作品、sound は 1,449・14作品。修飾句など複数の項目が同じ行に数えられ、族間・行の単純合算はできない。進捗 714、loot condition 271、entry 618、function 1,170 はそれぞれ定義ファイルへの対応数でコマンド行と比較できない。component は 1,702 行・12作品。観測されない用途も範囲に含む。行数は進行上の重要度でも実行成功率でもない。

推定：関数・状態・エンティティは多くのギミックの成立を支えるため先に置く。表示・音も条件付きチェーンの成否や操作可能性に影響し得るため、一律に任意とは扱わない。#69 の実例と #104 のギミック評価で実際の優先順位を見直す。粒子は ID 対応比 71.57% が描画成功率ではなく、実際の書き換え出力行は 4.02%。#135 の構文・成否の問題を残したまま視覚品質の段階まで先送りしない。

## M2 #93〜#104 の見直し

- #93 は #67 の委譲成否の不一致が課題。台帳の方式は未確認で runtime が 0 でも必要量ゼロを意味しない。#168 の後段が成否を使う箇所の集計を待ち、判断2の根拠にする。
- #94・#95 は決定済み。#99 は storage とスコアに限定し、entity/block の仮想 NBT を含めない。#98 は高頻度の execute/function を含むが、`on`・entity/block data・predicate などを明示的に除外しており、#179 と後続子 Issue で追う。
- #96・#97 は正解データと関数取込。#97 が扱わない進捗・predicate・ルートテーブルを報告し、各族で追う。#100 のマクロ、#101 の schedule は台帳の静的行数だけで動作やコストを評価しない。
- #102・#103 はホストとチェーン振り分けの共通基盤。粒子を含む後続機能が依存するが、その全実装を追加しない。#104 は既存の自作マップで M2 対象を確認し、未対応族を成功扱いしない。
- #165・#166 の構文調査と族の意味・実行検証は別。対象 JE 1.20.4 の反映 #164 と族別の版差も確認する。

## 反映と検証

各族の追跡 Issue に段階を割り当てる。具体的な実装は既存の依存を確認し、1 PR に収まる子 Issue とその完了条件に分割して進める。#106 のマージまでは追跡 Issue の依存を残す。
