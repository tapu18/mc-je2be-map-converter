# 成否を後段が使い、同期評価できない委譲（#168）

#93 の判断2（所有者、2026-11-22）の材料。後段が成否を使う経路で、ランタイムが同期で成否を評価できない委譲の命令がどれだけあるかを、配布マップ19本（`sample-map/`、git 管理外）で数えた。集計値だけを載せ、コマンドの文面と作品名は載せない。作品は ZIP 名の昇順の連番（0 起点、`scripts/dump_commands.py` と同じ）で示す。

対象は main `6092bac` の変換器とランタイム。数え方は `tools/success-consumers.ts`（下の「再現手順」）。

## 1. 同期評価できない委譲の命令

**委譲**は、ランタイムの中核が自前で評価しない末尾命令を、BE の `runCommand` に渡すことを指す（`docs/runtime-architecture.md` の「ネイティブ委譲（#309）」、`packages/core/src/runtime/world.ts` の `executeWorldCommand`）。

### 中核が自前で評価する命令（委譲しない）

ソースを読んだ範囲。それぞれの評価が Java と一致するかは、各機能の Issue とシナリオによる。

| 命令 | 根拠（main `6092bac`） |
| --- | --- |
| `scoreboard`（スコア族が `runtime` と判定する形） | `packages/core/src/features/score/registration.ts`、`runtimeFamilies`（`packages/core/src/runtime/command.ts`） |
| `data` の storage 対象 | `packages/core/src/features/storage/registration.ts` |
| `schedule` | `packages/core/src/features/schedule/registration.ts` |
| `function`、`return`（`return run` は中の命令による） | `packages/core/src/runtime/command.ts` の `execute` / `executeTerminal` |
| 位置・ブロックだけの `setblock`（NBT・タグ・`replace` 以外のモードを除く） | `packages/core/src/runtime/world.ts` |
| `execute` の修飾句と条件（`if block` / `blocks` は変換器が未対応とする） | `compileModifier`（`packages/core/src/runtime/execute-steps.ts`）、`unsupportedStep`（`packages/converter/src/command-chains.ts`） |

上記以外の末尾命令（`kill`・`fill`・`tp`・`tellraw` など）は、BE コマンドに書き換えられれば委譲し、書き換えられなければ未対応になる。

### 委譲の成否が同期でわかるか（文脈ごと）

| 文脈 | 委譲の成否 | 根拠 | 確度 |
| --- | --- | --- | --- |
| カスタムコマンドのハンドラ内（ランタイムに移したコマンドブロックのチェーン、`je2be:run` で起動した関数と、その呼び出し先） | **どの命令でも同期評価できない**。`runCommand` を呼べないため、ランタイムは `unknown` を返す | `node_modules/@minecraft/server/index.d.ts`（2.12.0-beta.1.26.66-stable）の `Dimension.runCommand`（9216行）と `Entity.runCommand`（10901行）は `@privilege no-restricted-execution`。ハンドラ内で `runCommand` が禁止されることは `design.md` 7章（#3、`poc/launcher`）で実測。実装は `packages/runtime-host/src/host.ts` の `deferChainCommand` と `restricted` | 実測（#3） |
| 書き込み可能な文脈（`load`・`tick` のタグ、`schedule` のコールバック。`system.runInterval` から動く） | `successCount` が同期で返る | `CommandResult.successCount`（`index.d.ts` 7553行）。同期で返り直後の読み取りに反映されることは `design.md` 7章（#3）で実測。実装は `packages/runtime-host/src/main.ts`（`completion: "synchronous"`） | 同期で返ること：実測。Java の `success` / `result` と値が一致するか：命令ごとに**未確認** |

したがって、#93 の判断2が対象とする「同期評価できない委譲」は、**ハンドラ内で動くすべての委譲**である。命令の種類では決まらず、どの文脈で動くかで決まる。書き込み可能な文脈では成否は得られるが、Java と同じ値かは確かめていない（BE の `successCount` は「適用に成功した対象の数」で、Java の `result` は命令ごとに意味が違う）。

## 2. 後段が成否を使う箇所の件数

### 数えたもの

後段は、PM の 11-25 の提案どおり、条件付きのチェーン・コンパレーター・`execute store success/result`・`execute if function`・`return run` に限った。関数をまたぐ推移的な依存は、変換器の判定（チェーンから呼ぶ関数をたどる）に含まれる分を除いて**未集計**。

- **判断待ち**：変換器（`prepareWorldCommands`）がチェーンを振り分け、理由が「#93 の判断待ち: 同期評価できない委譲の成否を後段が参照する」になったチェーン。今の変換器で、まさにこの判断で止まっているもの。
- **ランタイム移行**：変換器がランタイムに移したチェーン。この中に委譲の成否を使う箇所は、定義上ない（あれば判断待ちになる）。
- **他理由で対象外**：判断待ちより前に、別の理由（文法がない、ランタイムで未対応の修飾句、未対応のディメンションなど）で止まったチェーン。変換器はこの判定に達していない。そこで、後段（次の条件付きブロック、自身の `store`・`return run`、コンパレーター）が、中核で評価しない末尾命令の成否を使うブロックを含むチェーンを、別に数えた。他の理由が解消されたときに判断待ちになり得る数の目安（**推定**。ブロックの順序は変換器の組み立てに従い、合流・ループのチェーンでは近似）。「BE に書き換えられる」は、そのブロックが変換器のレポートで `unsupported`・`invalid` でないもの。
- **コンパレーター**：コマンドブロックの入力側に接したもの（JE の `facing` が入力の向き。`scripts/survey_corpus.py` の `geometry()` と同じ）。固体ブロック越しの読み取りは数えていない。
- **関数**：データパックの関数（後から読むパックの上書きを適用）の行。末尾命令が委譲になり、その成否・結果を `execute store` か `return run` が使う行。`load`・`tick` から動けば成否は同期でわかる（上の表）。チェーンから呼ばれた場合は、変換器がチェーンの判定でたどる。

件数の単位：チェーンは「チェーン数（ブロック数）」。関数は「行数（関数の数）」。

### 限界

- 文法のない古い版の作品が2本（1、3）あり、計 222 チェーンを判定できない。ワールドを含まない ZIP が1本（4）。
- 他理由で対象外の 1,370 チェーンのうち、「ランタイムパックを初期化できない」129（5作品。関数タグの解決などに失敗）と「ランタイムで未対応のディメンション」398（1作品）は、変換器の別の制限で止まっている。上の「後段が使う」の目安は、その制限が解消された後の判断待ちの上限ではなく、ブロック単位の構造だけを見た近似。
- 関数をまたぐ推移的な依存（関数の `return` を `execute store` で受ける、など）は、チェーンから呼ぶ関数を変換器がたどる分を除いて未集計。
- チェーン間の依存（あるチェーンの成否や比較器出力を、別のチェーンや回路が使う）は数えていない（#236・#103）。
- 2回実行して同じ JSON を得た（決定的な処理のため、実行ごとの揺れはない）。

## 3. 再現手順

```sh
npm run setup:servers && npm run setup:mappings && npm run setup:grammars
node tools/success-consumers.ts <sample-map のディレクトリ> --json <スクラッチ>/success-consumers.json
```

標準出力に作品ごとの表、`--json` に全カウンタを出す。ZIP は一時ディレクトリに、ワールドの `level.dat`・`region`・`datapacks`・`data` だけ展開し、終わったら消す。原本は読むだけ。出力に文面・作品名は含まれないが、`--json` の出力先もリポジトリの外に置く。
