# 版別のコマンド文法（#58・#70）

Java サーバーの固定版とは別に、対象の安定リリースのサーバーから `commands.json` を生成する。
BDS や `tools/servers.json` の版を切り替えるものではない。

## 生成と選択

```sh
npm run setup:servers
npm run setup:grammars
# 一部の版だけ必要な場合
npm run setup:grammars -- 1.20.6 1.21.4
```

取得元と SHA-1 は `tools/java-grammars.json`、現行版は `tools/servers.json` に固定する。
アーカイブは `JE2BE_GRAMMAR_CACHE` または `~/.cache/je2be-grammars` へ保存し、取得後も
キャッシュ利用時も SHA-1 を照合する。実行には `setup:servers` が用意する JRE を使う。
出力は git 管理外の `servers/grammars/<版>/`：

- `server/`: 当該版のサーバーと、実機検証専用のワールド・ログ
- `generated/reports/commands.json`: 当該サーバーのデータ生成器が出す文法
- `grammar.json`: DataVersion・パック形式・テキスト形式・元サーバーの取得元とハッシュ・文法の SHA-256

サーバー配布物中の `version.json` から DataVersion とパック形式を読む。数値を版名から推測しない。
データ生成器の出力とサーバーの作業先は別ディレクトリにする。
ゲーム由来の文法やサーバー本体をリポジトリには含めない。

`@je2be/converter` の `loadJavaGrammars()` / `loadGrammarTree()` で生成済みの文法を読み、
`@je2be/core` の `selectCommandGrammar()` に渡す。

1. ワールドの DataVersion があれば、**その版に一致する文法だけ**を選ぶ。
2. DataVersion がない単体パックは `pack_format` で選ぶ。同じ形式に複数の文法があれば、
   文法の SHA-256 とテキスト形式が一致する場合だけ共通の代表を選ぶ。
3. 文法が未生成・版が不明・異なる文法で曖昧な場合は、`unavailable` / `ambiguous` を返す。
   近い版や最新版に黙って置き換えない。

DataVersion とパック形式の両方がある場合はワールドの DataVersion を優先する。
古い形式を宣言したパックを新しいワールドで使うこともあるため、数値が一致しないだけでは拒否しない。
1.20.4 の文法は #191 で正式カタログに登録した。調査時の生成結果は `docs/research-1204.md`。現在は 1.20.4 / 1.20.5 / 1.20.6、1.21〜1.21.11 の全安定リリース、および 26.1 / 26.2 / 26.3 を固定している。
上表以外の修正版、プレリリース、スナップショットは対象外。
追加する場合は、公式の取得元・ハッシュ・関数ディレクトリ名を固定して同じ実機比較を行う。
同じパック形式を共有する41・48・57・81・88では、今回生成した各版の文法のSHA-256は一致した。
これは今回の固定版での結果であり、同じパック形式なら常に文法が同じという前提にはしない。

## 1.20.4 → 1.20.5 の正規化（#308）

1.20.4 の文法では `id{NBT}` を読み、カスタム NBT をアイテム引数では `custom_data={...}`、
アイテム述語では部分一致の `custom_data~{...}` に変える。整数の `CustomModelData` は
`minecraft:custom_model_data` に移し、述語は整数の一致を照合する。1.21.4 の境界では
この整数を `floats` の先頭の値に変える。精度を失う整数や、述語が別の整数にも一致する
丸めは診断する。ブロック・エンティティの既知の
アイテム位置からカスタムフィールドを読む NBT パスは、`tag.<field>` から
`components."minecraft:custom_data".<field>` に変わる。コマンド storage のパスはそのまま使う。
JSON テキストの `show_item` は、文字列と真偽値の型を保持できるカスタムデータを
`contents.tag` から `contents.components` に移す。

`HideFlags` など個別の変換を要するキー、`tag` 全体の参照・書き込み、
変換できないフィルタ、型を保持できないホバーは、元の引数位置を付けて診断する。
旧 particle と effect はそれぞれ #135・#147 と #181 で扱う。

## ワールドのコマンド書き換え（#72）

`convertWorld` の `rewrite` オプションはワールドの DataVersion を使って文法を選ぶ。
固定版（現在は26.3）の文法は `setup:servers` が生成する。旧版を変換する場合は、あらかじめ
`npm run setup:grammars -- <対象版>` でその版の文法とブロックの既定状態を生成する。
対象の文法がない場合は、各コマンドブロックを `unsupported` としてレポートに残す。
ブロック・アイテム・サウンド・パーティクルの BE 対応には固定 Geyser 表を使う。

## コーパスでの利用

```sh
python3 -I scripts/dump_commands.py sample-map > /tmp/commands.jsonl
node tools/parse-corpus.ts /tmp/commands.jsonl
node tools/parse-corpus.ts /tmp/commands.jsonl --java
```

`parse-corpus.ts` は行ごとの版で文法を選ぶ。`文法なし` の行は構文エラーとは別に数え、
パース成功率の母数からも分ける。`--java` は、選んだ文法のサーバーへ同じコマンドを渡す。
重複は「版とコマンドの組」で除き、版が違う同一文字列を混同しない。
データパック内の定義はこの集計では読み込まないため、参照不足と値の検証による差は残る。
パックを含む追加検証は `docs/command-validation.md` を参照。

`--commands <commands.json>` は手動指定の調査用として残す。この場合は指定者が版を判断する。
ファイルだけでは実行する Java 版を確定できないため、`--commands` と `--java` は併用しない。
集計以外の失敗コマンド・診断の詳細は公開しない。

## 実測した境目と書き換え候補

根拠は `packages/bridge/src/versioned-grammar.servers.test.ts`。次の形式を各リリースの
`checkJavaSyntax` と、その版の文法を使うパーサで比較する。

| 形式 | 1.20.5〜1.21.4 | 1.21.5〜1.21.8 | 1.21.9 / 1.21.10 | 1.21.11 / 26.1〜26.3 |
| --- | --- | --- | --- | --- |
| `tellraw @a {"text":"x"}` | 受理 | 受理 | 受理 | 受理 |
| `tellraw @a {text:'x'}`・`{text:"x",bold:1b}` | 拒否 | 受理 | 受理 | 受理 |
| JSON のスラッシュのエスケープを含むテキスト | 受理 | 拒否 | 拒否 | 拒否 |
| `gamerule keepInventory true` | 受理 | 受理 | 受理 | 拒否 |
| `gamerule keep_inventory true` | 拒否 | 拒否 | 拒否 | 受理 |
| `setworldspawn 0 64 0 ~15` | 受理 | 受理 | 拒否 | 拒否 |
| `setworldspawn 0 64 0 90 0` | 拒否 | 拒否 | 受理 | 受理 |

テキスト形式の境目は安定リリース1.21.4と1.21.5で確認した。`textFormatFor` は
DataVersion 4325、パック形式71を境にする。スナップショットでの最初の導入版は対象外。
JSON 指定時は JSON の文字列・配列・複合値の終端を読み、JSON 構文を検証してから
既存のテキスト中間表現へ正規化する。JSON 固有のエスケープを SNBT として先に拒否せず、
逆に SNBT 専用表記を JSON として受理することも防ぐ。

書き換えの候補は、旧 gamerule 名、旧 `minecraft:angle`（単一の角度）から新しい回転引数への対応、
JSON / SNBT のテキストから BE rawtext への変換（#62）。
安定リリースでは、回転引数の変更は1.21.9、調べたgamerule名の変更は1.21.11が最初だった。
BE側の正しい引数はこの比較では確定しない。追加の実測なしに一律置換しない。
旧文法の `minecraft:color` と現行の `minecraft:team_color` は色名と `reset` を読み、
装飾名 `bold` を色として受理しない。

## 対象版の追加による集計の変化（#70）

2026-11-16、同じ19本のローカルコーパス115,487行を追加前後で再集計した。
マクロ3,630行はパース対象から分離する。コマンド本文・作品名は掲載しない。

| 区分 | 追加前 | 追加後 |
| --- | ---: | ---: |
| 文法なし | 26,903 | 18,924 |
| パース対象 | 84,954 | 92,933 |
| パース成功 | 84,905 | 92,875 |

追加したDataVersion 3953は5,474行中5,470行、4903は2,505行中2,500行がパース成功。
両版の「文法なし」は0になった。残る18,924行は対象外のDataVersion 3465が5行、
3700が16,450行、版情報不明が2,469行（当時の対象・実装による集計）。近い版の文法で成功扱いにはしない。
これは構文を読めた行数であり、BEへの変換成功・ギミックの成立・クリア可能性は示さない（#47・#69）。

再現コマンドは上記 `dump_commands.py` と `parse-corpus.ts`。
