# ランタイムの構成

#141 の調査に対する #95 の所有者承認（2026-11-22）。実装は骨組みのみで、以下は目標の契約である。#93 の方式 A と #94 の状態設計に従う。

## 境界

解釈中核は Minecraft 非依存の `packages/core` に置く。既存のパーサと NBT の型を共有できる。別パッケージ案は公開境界と依存管理が増えるため採らない。Script API ホストは別パッケージ、生成パックの組み立ては converter が担う。`bridge-pack` は検証専用で製品は依存しない。ホストパッケージの名前と実装は未確定。

## ホスト契約

中核が Java の条件、セレクタのフィルタ・sort・limit、成否、分岐、予算を評価する。ホストは候補エンティティ、ブロックと状態の読み書き、ネイティブ委譲、保存、時刻を提供する。ホストにセレクタ全体を委ねる案は Java の意味が分散するため採らない。候補順、距離、乱数、失敗、未ロード領域を明示してフェイクで再現できるようにする。候補集合の Java と BE の一致は未確認。

#93 の方式 A として同期読み取り、保留書き込みのオーバーレイ、同期成否を要する。スコアは #94 のとおりランタイムが正本、BE は投影である。同期評価できない委譲の成否を成功と偽らない。成否に依存するチェーンを全体的に移すか静的処理の対象外にするかは #93 で未決定。共有状態はランタイムに寄せ、検出できない競合は警告する。起動直後のずれは許容し、稼働中の tick のずれは致命的とする。

## 受け渡しとビルド

通常の関数は変換時に解析し版付き IR で渡す。IR 版と入力文法版を記録し、未知版と非対応命令を黙って実行しない。全本文をゲーム内でパースする案は反復解析と文法依存が増えるため採らない。IR の具体的なスキーマと互換性は未確認。マクロは静的な穴付き型紙の調査 #155 の結果を待つ。文法・対応表の同梱と権利は #107 で判断待ちである。

[PoC](../poc/runtime-load/README.md) の BDS 1.26.63.1 で文法・対応表・パーサを含むパックは圧縮前 12,624,623 bytes、起動要求から初回パースまで 602 / 783 / 613 ms（ワールド準備を含む）、JSON.parse は 159 / 193 / 178 ms。再構成データ案は 12,210,907 bytes、手書き1命令・石1件の限定例は 50,929 bytes。後者は全機能版ではなく、実用版の大きさと性能は未確認。

出力時に必要なモジュールだけを束ねる。bridge-pack と同じ tsc 出力だけの案は core の `.ts` 相対 import とデータの扱いを別途解決する必要がある。`erasableSyntaxOnly` と `.ts` 相対 import を維持し、成果物の import 解決と Node API 不在を BDS で検証する。製品用の束ね方と起動性能は未確認。

## 解釈と検証

明示的なフレームと実行キューで関数呼び出し、return、分岐を表す。起動ごとの命令数・深さ・分岐数に予算を持たせ、超過やエラーを成功扱いせず診断する。再帰的な直接呼び出しは深さと中断の制御が難しいため採らない。Java の正確な上限、順序、エラー伝播は未確認。方式 A はハンドラ内で同期実行し、保留書き込みを後で反映する。

Node のフェイクホストでは Java の正解データ（#96）と意味論を比較する。BDS では API 制約、起動、永続化、ネイティブとの境界を検証する。片方だけではそれぞれ API の制約または網羅と再現を確かめにくい。骨組みは単一の文字列保持者への `scoreboard players set` のみで、セレクタ、関数、保存、実機ホスト、版付き IR は後続作業である。
